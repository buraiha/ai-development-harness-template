# Project-Specific Rules

このファイルには、AIの調査、変更、検証へ直接影響するプロジェクト固有ルールだけを記載する。

AIの共通行動規範は `AGENTS.md` と `.ai/common.md`、プロジェクトの詳しい仕様や設計は `README.md` と `docs/` を参照すること。このファイルへプロジェクト情報をすべて複製しない。

> 導入時に山括弧の例を、リポジトリで確認した事実へ置き換える。該当しない項目は削除する。推測した仕様、未導入のコマンド、秘密値は記載しない。

## Project Specific Rules

- このプロジェクトは `<アプリケーション、CLI、ライブラリなどの短い説明>` である。
- 必要に応じて `<README.md または docs/内の関連文書>` を参照し、既存設計を理解してから変更する。
- `<維持すべきディレクトリ構成、責務、依存方向>` を維持する。
- `<DBスキーマ、公開API、保存形式など>` の変更が必要な場合は、影響と移行方法を事前に明示する。
- `<認証、権限、個人情報、実運用データなど>` を扱う既存の安全境界を弱めない。
- 依存ライブラリの追加や更新は必要最小限にし、既存のマニフェストとロックファイルの整合性を保つ。
- 既存のマニフェスト、スクリプト、CI設定、README、テストを調査し、変更内容に関係する既存の検証手段を使用する。
- `<そのほか、AIが変更時に必ず守るべき固有ルール>`

## 補足が必要な場合のみ追加する項目

次の情報は、AIの判断へ直接影響し、`README.md` や `docs/` への参照だけでは不足する場合に限って追記する。

- 変更してはいけない実運用データやローカルファイル
- 維持すべき認証scope、テナント境界、入力検証
- タイムゾーン、文字コード、後方互換性などの不変条件
- 変更種別ごとに必須となる既存の検証
- 明示的な依頼なしに操作してはいけない本番・外部環境

プロジェクトの成長やAIの実際の失敗に合わせて、必要なルールだけを追加する。最初から想定上のルールを網羅しない。
